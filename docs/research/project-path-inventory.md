## 0. Terminology (CONTEXT.md)

- **Provider** = a telemetry source in the pipeline (`src/main/pipeline/providers/*`): it scans on-disk session data into the ledger. This doc is about providers only.
- **Harness** = a user-installed coding-agent CLI the app drives over ACP (`src/main/agents/harnesses/*`, registry `src/main/agents/harnesses/index.ts:26-41`, 14 specs: claude, codex, opencode, grok, gemini, goose, qwen, kimi, copilot, cline, kilo-code, cursor, droid, pi). Harnesses drive Coach chat; they do NOT emit `project`/`projectPath`/`workingDirectory` into the ledger. Name overlap (e.g. `claude` provider vs `claude` harness, `opencode` provider vs `opencode` harness) is attribution-relevant but out of scope for the identity rule except as a glossary guardrail.

## 2. Parser seam (`src/main/pipeline/parser.ts`)

- `normalizeProjectPathKey` (`parser.ts:103-106`): `trim` → `\`→`/` → strip trailing `/+` → `toLowerCase()`. Used for the Claude `projectKey` (`parser.ts:2450-2452`). Lowercases but does NOT resolve symlinks, `..`, or drive-letter case beyond lowering.
- `projectNameFromPath(path, fallback)` (`parser.ts:108-111`): same slash/trailing normalization, last non-empty segment, else fallback. Used for worktree rename (`parser.ts:2219,2281,2651`).
- `resolveCanonicalProjectPath` (`parser.ts:135-176`): trims; non-absolute-on-current-platform (win32 `X:/`, else leading `/`) returns `{path: cwd, isWorktree: false}` untouched (foreign-path guard). Walks up: `.git` **directory** → not a worktree, returns original `cwd` verbatim (even if `dir !== trimmed`, i.e. parent `.git` does NOT re-root); `.git` **file** with `gitdir: …/.git/worktrees/<name>` → `{path: <main-repo>, isWorktree: true}` (slashes normalized); missing/unparseable marker or filesystem root → not a worktree.
- `isCoworkSession(cwd, filePath)` (`parser.ts:125-133`): true if resolved cwd OR resolved JSONL path is under any `getDesktopSessionsDirs()` base (local-mode ephemeral `outputs/` cwd + container-mode `/sessions/<name>` cwd, detected via file path). Callers skip canonicalization entirely (`parser.ts:2217,2275`).
- `claudeSlugFallbackPath(dirName)` (`parser.ts:96-101`): identity — dash may be separator OR literal, so never invent segments.
- `extractCanonicalCwd` (`parser.ts:1782-1789`): FIRST non-empty trimmed `entry.cwd` in the journal wins. `parseSessionFile` (`parser.ts:1933-2004`) + append path (`parser.ts:2209-2220`) + full re-parse (`parser.ts:2274-2281`) all feed it; Cowork-guarded before canonicalize; first-cwd-wins across appends (cached region wins, `parser.ts:2209-2211`).
- `canonicalizeProviderCallProject` (`parser.ts:2642-2654`, applied to every generic-provider call at `parser.ts:3179`): no `projectPath` → untouched; non-worktree → fills `workingDirectory ??= projectPath`, keeps `project`; worktree → `workingDirectory ??= projectPath`, `project = basename(canonical)`, `projectPath = canonical`.
- Grouping, Claude path (`scanProjectDirs`, `parser.ts:2047-2487`): `projectKey = normalize(canonicalCwd) ?? 'slug:'+dirName`; `projectName = canonicalProjectName ?? dirName`; `projectPath = canonicalCwd ?? slugFallback`; anchors (0-cost) bucketed separately; trailing fold merges `slug:*` entries into cwd-keyed entries by `dirName` (`parser.ts:2463-2479`); `summarizeProject` (`parser.ts:2496-2510`) rolls up + sets `totalProxiedCostUSD` when under `proxyPaths`.
- Grouping, generic path (`parser.ts:3330-3443`): `sessionMap` key = `provider:sessionId:project` where `project = turn.calls[0]?.project ?? source.project` (durable orphans: `?? providerName`); first-seen `projectPath`/`workingDirectory` win per session; final `projectMap` key = bare `project` string; `projectPath ??= unsanitizePath(dirName)` (`unsanitizePath`: `-`→`/`, `parser.ts:53-55`) — i.e. generic providers RE-INVENT segments from dashes, the exact thing the Claude path refuses to do.

## 3. Aggregation seam (ledger query-time)

- `buildSessionSummaries` (`src/main/store/aggregate.ts:435-481`): reassembles turns/calls from flat ledger rows keyed by `(sourceId, sessionId, turnIndex)`; session identity passes through (`assembleSession` sets `summary.project = session.project`, `aggregate.ts:380`, plus `workingDirectory`/`repoUrl` attachments). No re-normalization here.
- `buildSessionRows` (`aggregate.ts:489-491`): `summaries.map(s => sessionRowFromSummary(s, s.project))` — project label threads straight into the Sessions-section row.
- `groupSummariesIntoProjects` (`aggregate.ts:501-519`): key = **exact `session.project` string** (no `normalizeProjectPathKey`, no lowercase). `projectPath = first workingDirectory ?? project`; `repoUrl = first repoUrl`. Consumers: Optimize/Yield detector cores + export reassembly (`optimize-view.ts:2287-2291`, `yield-view.ts:386-390`, `views.ts:270`).
- Views group by the same verbatim label: Spend (`spend-view.ts:123-125,152-195`: `matrix project→model→cost`, daily `byProject` segments, top-8+Other flow); Sessions (`sessions-view.ts:16-19`: rows newest-first, no regroup); Overview (`overview.ts:669-682`: `buildSessionSummaries` twice — lifetime for `dataStart`, scoped for payload; `inScope` filters on first-turn date + any-call provider, `overview.ts:112-123`; project labels only surface via downstream breakdowns, not Overview KPIs). `views.ts:153-164,315-317,373` likewise `Map` on verbatim `s.project`.
- `repoUrl` role: purely informational/display. Legacy `attachRepoUrls(projects)` runs `git remote get-url origin` in `project.projectPath` (`git-remote.ts:14-50`, `shortenRepoUrl` pretty-prints). Live path: `db-worker/context.ts:115-130` memoizes `getRepoUrl(canonicalCwd)` per scan and passes it into `ledger.portIn`; `ledger.ts:250,278-302` upserts it onto `ledger_source.repo_url` (and discovery `project` onto `ledger_source.project`); `aggregate.ts:460-477` reattaches `repoUrl` from source onto each session summary. Non-git cwd / missing remote / git absent / timeout → `undefined`, silently. Only `canonicalCwd` (Claude-path files) feeds the lookup — generic providers' `projectPath` does not.

## 4. Port-in precedence (`src/main/store/port.ts:54-86,124-143`)

- Session: `projectPath = cachedFile.canonicalCwd ?? delta.workingDirectory ?? dirName(file's parent dir)`; `project = delta.project (source.project) ?? canonicalProjectName ?? dirName`; `workingDirectory = delta.workingDirectory ?? cached.workingDirectory ?? null`. Comment (`port.ts:56-58`) calls out the pre-fix symptom: without discovery metadata, non-Claude providers degrade to the directory UUID.
- Call: `project = raw.project ?? session.project; projectPath = raw.projectPath ?? session.projectPath; workingDirectory = raw.workingDirectory ?? session.workingDirectory` (`port.ts:141-143`). So Codex/Copilot-style per-call paths survive; OpenCode/Cursor/Gemini-style path-less calls inherit the session/file-level label.

## 5. Open questions for the identity decision (#95+)

1. Canonical key: `normalizeProjectPathKey(canonicalCwd)` (lowercased absolute path) vs verbatim `project` label? Today Claude groups by normalized path while `groupSummariesIntoProjects` groups by verbatim label — same repo spelled two ways (case, slash, trailing) splits downstream but not upstream.
2. Slug direction: extend `claudeSlugFallbackPath` (never invent segments) to the generic `unsanitizePath` (`-`→`/`) path, or vice versa? They currently contradict.
3. `basename` vs full-path sanitize: Copilot-JSONL/Antigravity/Grok (`basename`) collide on common leaf names (`api`, `app`) where Codex/OpenCode (`a-b-c` slug) do not. Which wins?
4. `repoUrl` as identity? Today display-only and only populated from `canonicalCwd`. Promoting it to (part of) the key would unify renames/moves but needs a story for non-git dirs, missing remotes, and multi-remote repos.
5. Worktree scope: `resolveCanonicalProjectPath` folds LINKED worktrees (`.git` file + `worktrees/` marker) to main repo but leaves parent-`.git`-dir nesting untouched. Confirm that is the intended boundary (submodules? nested repos? symlinked checkouts? Windows junctions?).
6. Cowork coverage: `isCoworkSession` keys off `getDesktopSessionsDirs()` (env-overridable, platform-specific, cached). New desktop layouts or container cwd shapes silently fall back to cwd-derived keys — needs an allowlist-update story.
7. `source.project` trust: port-in prefers discovery `project` over cache `canonicalProjectName`. For providers whose discovery label is a guess (JetBrains git-walk, Copilot sessionId fallback, empty-string OpenCode), should the per-call `projectPath`-derived name override instead?
8. Migration: re-scan (re-derive keys from transcripts, needs `sectionNeedsPrEvidenceReparse`-style one-shot) vs ledger migration (rewrite stored `project`/`project_path`) vs dual-read. Durable providers (OTel) never clear on `modified` (`ledger.ts:255-257`) — their rows pin old keys longest.
