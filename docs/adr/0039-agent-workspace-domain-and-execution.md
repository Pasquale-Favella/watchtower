# Agent workspace identity and execution ownership

Status: accepted as the M0 domain direction; protocol conformance, persistence and packaged application gates remain pending.

Related work: [issue #178](https://github.com/Pasquale-Favella/watchtower/issues/178), implemented incrementally in [PR #179](https://github.com/Pasquale-Favella/watchtower/pull/179).

This amends the ACP-only Harness definition in ADRs 0016 and 0018 for the general execution contract. Their current Coach implementation remains until its migration to the common execution service. The temporary workspace in ADR 0019 remains valid for that legacy consumer; it is not the durable checkout model. ADRs 0034 through 0038 retain schema, runtime, IO, RPC and import ownership.

The workspace domain has distinct Project, WorkspaceCheckout, Task, Conversation, AgentSession and AgentRun identities. A Task owns the objective and delivery lifecycle; a Conversation owns dialogue; an AgentSession associates one native conversation with its connection, driver and checkout; an AgentRun is one immutable attempt. A retry creates a new Run linked to its predecessor. A Task may remain in review or open after a Run completes, and a launch failure may produce a Run before a native session exists. Keep workflow, assignment, schedule and bot records out of the initial model until their phases require them. Preserve the existing glossary meaning of Artifact for packaged installers; execution output is WorkArtifact.

Core defines an Effect Schema contract for the session protocol. A driver connection is acquired within a caller-owned Scope and owns protocol resources and cleanup. Session load is explicit and never falls back to a fresh session. Submission carries immutable Run identity; interruption, steering, request response and reconciliation bind to the expected session generation and native identity when available. Native turn IDs may be unavailable and are not fabricated. Unsupported operations return a typed failure, delivery uncertainty remains explicit, reconciliation labels replay, and a closed event stream alone does not mean success. Capability support is supported, unsupported or unknown with evidence and restrictions; the application never promotes an unverified feature into a guarantee.

This boundary preserves native control semantics while allowing different transports to implement the same application vocabulary. Watchtower owns its operational state and persistence; each integration remains authoritative for its native session. The workspace store, application event ingestion, scheduling, filesystem and platform adapters remain separate from these core records and are introduced in their own slices. This initial domain and port implementation does not establish protocol parity, recovery correctness or distribution readiness; those remain explicit acceptance gates.

The alternative was to extend the Coach event stream and opaque resume cursor as the operational model. That would leave UI connection lifetime, native context and the user's objective coupled, and would lose native request and replay semantics at the language-model boundary. The new contract requires adapters and durable identity mapping, but it allows capability-specific behavior without a second execution engine. Infrastructure keeps native SDK types out of the core, and pure lifecycle calculations remain ordinary TypeScript functions.
